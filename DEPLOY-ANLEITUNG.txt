3) ⚠️ DER WICHTIGSTE PUNKT: NGINX MUSTER
-----------------------------------------
Dein nginx schickt bei JEDER unbekannten URL die index.html mit Status 200.
Damit ist eine nicht vorhandene "maxichen-v4.15.apk" plötzlich HTML mit
.apk-Endung → Android sagt "Paket ungültig". Genau das war live zu sehen:

  /app/maxichen-v4.15.apk  → 200, text/html, 130.871 B   ← falsch!
  /app/maxichen-v4.13.apk  → 200, 32.178.715 B           ← alte Datei noch da

So muss es aussehen — in /etc/nginx/sites-available/maxichen.de:

    # Dateien IMMER echt ausliefern, nie auf index.html fallen lassen
    location ~* \.(apk|zip|exe|svg|woff2|png|js|css)$ {
        try_files $uri =404;
    }

    # Nur die Seiten selbst dürfen auf index.html zurückfallen
    location / {
        try_files $uri $uri/ /index.html;
    }

WICHTIG: Der Datei-Block MUSS VOR dem location / stehen.
Reihenfolge zählt bei nginx: der erste passende Block gewinnt.

Dann:
  sudo nginx -t          # Syntax prüfen
  sudo systemctl reload nginx

8) 🔑 GEHEIMNISSE — ZWEI ORDNER, NIE IM ZIP, NIE AUF GITHUB
------------------------------------------------------------
  Lovechat/keys/                 (Ordner 700)
     release.jks                 (600)  Release-Schlüssel
     password.txt                (600)  Passwort dazu

  Lovechat/owner/                (Ordner 700)
     credentials.env             (600)  Mail-Passwort, Tokens, Owner
     accounts.json               (600)  Konten + Ablageorte

Beide sind ABSICHTLICH NICHT im Lovechat-FINAL-v4.15-SECURE.zip.
Grund: Ein ZIP wandert herum (USB-Stick, Cloud, Mail). Wer den Schlüssel
hat, kann gefälschte Updates bauen, die Android als echt akzeptiert.
Wer credentials.env hat, kommt an dein Postfach und deinen Owner-Account.

Im ZIP liegen nur die Vorlagen:
  keys/README.md · keys/*.example
  owner/README.md · owner/*.example

→ Sicherung: 2 USB-Sticks, offline, getrennt vom Projekt.
→ Bei GitHub: .gitignore schließt beide Ordner datei-genau aus
  (README und .example bleiben drin, damit das Repo verständlich ist).
→ Verloren = kein Update mehr möglich. Alle müssten deinstallieren.

ENV auf dem Server laden — SICHER (nicht mit export $(cat ... | xargs),
das zerlegt Passwörter mit Leerzeichen oder & ):

  cd ~/Lovechat
  set -a; . ./owner/credentials.env; set +a
  node server/server.js

  oder:  bash tools/load-env.sh --start

Nach jedem Upload prüfen, dass nichts ausgelaufen ist:
